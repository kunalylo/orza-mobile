## Bugs

| # | Bug | Status |
|---|-----|--------|
| B1 | Ask ÖRZA header: the title "Ask ÖRZA" (variant `title`, letterSpacing −0.1, shrink-wrapped in a row with the online dot) was measured a hair narrower than Android draws it, so "ÖRZA" wrapped onto a clipped second line — the header read "Ask" (co01). Same class as EmptyState/alarm B2. Fix `src/app/(app)/ask.tsx`: title `letterSpacing: 0` | FIXED, retested co02z |
| B2 | Chat replies: the coach prompt (web `coachSystemPrompt`) lets the AI link app pages as markdown with website paths (/dashboard/meals, /dashboard/compensation, /dashboard/recipes …); RichText rendered every non-https link as plain text, so those links were dead on the phone. Fix: new `src/features/chat/links.ts` (`appLinkFor` maps /dashboard/<page>[?date=] to the app screen; `openAppLink` switches tab or pushes the screen) used by `RichText.tsx` | FIXED, retested co11z |
| B3 | New chat from the conversations sheet: `newChat` focused the composer in the same frame the sheet started closing — the field counted as focused while the sheet's Modal window still had window focus, so Android never showed the keyboard. Fix: `Sheet` gets `onClosed` (fires once the sheet unmounted); `ask.tsx` focuses the composer from there, retrying blur+focus up to 3× on Android while no keyboard came (`focusComposer`) | FIXED, retested co13_newchat |
| B4 | Voice (chat + meal composer, `src/lib/voice.ts` `ensurePermission`): asked for the mic only when `getPermissionsAsync().canAskAgain`. On Android Expo derives that from the LAST request's result (persisted `blocked:RECORD_AUDIO` in `expo.modules.permissions.asked`), so once blocked it stays false even after the member resets the permission in Settings → the app showed "Open Settings" forever and never asked. Fix: on Android always request when not granted (a blocked request returns at once without a dialog and re-derives blocked) | FIXED, retested |
| B5 | Recipe prompt (`RecipeGenerator.tsx`): a single-line TextField; Android wraps a single-line field's long placeholder onto a second line that the one-line height clips, and a 300-character request scrolled out of sight. Fix: the prompt is multiline (grows to ~5 lines, `submitBehavior="blurAndSubmit"` so the "go" key still generates, text centred) | FIXED, retested co24/co25 |
| B6 | Recipes screen: deleting the open result's recipe on its detail screen shrinks the content (result card closes, list empties); Android kept the old scroll offset past the end, so the screen came back mostly blank until touched. Fix `recipes.tsx`: track offset + viewport, clamp in `onContentSizeChange` | FIXED, retested co36 |
| B7 | Recipes generate failure: `runGenerate` scrolls down to the "cooking" card; on an error the card goes away but the view stayed there — the studio (field errors such as a prompt error are shown only there, without a toast) and "Generate recipe" were off screen. Fix `recipes.tsx`: scroll back to the top on failure | FIXED, retested co38 |
| B8 | Rebalance: after a plan is created `onCreated` scrolled to `resultY` after a fixed 120 ms; the first plan's section had not laid out yet (resultY 0) so the view scrolled to the TOP of the form — the plan was off screen below. Fix `rebalance.tsx`: reveal from the section's own `onLayout` (`revealPending`), fixed delay kept only when the section already has a position | FIXED, retested co49 |
| B9 | Rebalance plan note: "never below {floor} kcal a day" when the floor (BMR 1,696) is above the member's usual target (1,680) contradicted the day cards. Fix `PlanView.tsx`: different wording when floor ≥ usual (web `RebalancePlanView.tsx` has the same sentence) | FIXED |
| B10 | Rebalance history row: the chevron sat outside the row's pressable, so tapping it did nothing. Fix `PlanHistory.tsx`: chevron is a Pressable toggle too (hidden from accessibility — the row is the button) | FIXED, retested co51 |
